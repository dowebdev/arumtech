# ADR-0003 — 통합 검색: 서버 렌더 + 게시판 로컬 필터

- 상태: 채택 (Accepted)
- 날짜: 2026-07-23

## 배경 (Context)

상단 바에서 사이트 전체를 검색하는 "통합 검색"을 요구받았다. 그런데 검색 대상
콘텐츠의 출처가 둘로 나뉜다.

- **제품** — 정적 `lib/data.ts`. 모델·영문타입·kicker·라인·태그 등 리치 필드.
- **자료실·설치사례·공지(뉴스)** — 외부 게시판 API(`lib/contents`, woori `/contents`).
  구 사이트에서 옮겨온 게시글(자료실 137건, 설치사례 100건 등)이 런타임에 조회된다.
  (`lib/data.ts` 의 `downloads`/`news`/`cases` 배열은 홈 대표섹션 등에만 쓰이는 레거시다.)

게시판 API에는 `search` 파라미터가 있지만 **대소문자를 구분**한다. `search=B-18` 은
3건을 주지만 `search=b-18` 은 0건이다. 사용자는 소문자로 입력하므로 이걸 그대로 쓰면
게시판 결과가 조용히 누락된다. 이는 제품 검색에 적용한 규칙(대소문자 무시 토큰 AND)과도
어긋난다.

## 결정 (Decision)

**`/search?keyword=` 를 서버 컴포넌트로 렌더한다. 매칭 규칙(소문자화 후 공백 토큰 AND
부분일치)을 제품과 게시판 전체에 일관되게 적용한다.**

- **제품**: `lib/data.ts` 를 서버에서 필터. 색인 필드 = 모델·en·kicker·라인·태그·열모델명.
- **게시판**: API 의 대소문자 구분 `search` 를 쓰지 않고, **목록 전체를 서버 캐시로 받아
  (`fetchContentsList(..., { limit: 300, revalidate: 300 })`) 우리 코드에서 필터**한다.
  색인 필드 = 제목·카테고리 (목록 API 는 본문을 주지 않는다). 설치사례만 썸네일을 위해
  `withContent: true`.
- **결과 표시**: "통합 검색 · N개의 검색 결과" + 유형별 그룹(제품→설치사례→자료실→뉴스),
  각 유형 개수 배지. 유형별 맞춤 카드(썸네일+메타), 제목 키워드 하이라이트. 섹션당 최대
  24건 표시(초과 시 안내).
- **진입점**: 헤더 우측 돋보기 아이콘(데스크톱·모바일 공용) → 바 아래 전폭 드롭다운 →
  네이티브 폼 GET 으로 `/search?keyword=` 이동.

## 결과 (Consequences)

- 매칭 규칙이 제품·게시판에서 동일하다. 소문자 모델 검색(`m-f3a`, `b-18`)이 게시판까지
  정상 매칭된다.
- **외부 게시판 API 에 의존한다.** API/설정 장애 시 해당 게시판 섹션은 조용히 생략하고
  안내 한 줄을 노출한다(제품 결과는 정상). 검색 페이지는 `force-dynamic`.
- 게시판은 **제목·카테고리만 색인**한다. 본문 검색이 필요해지면 상세 색인/검색 엔드포인트를
  별도로 도입해야 한다.
- `revalidate: 300` 으로 목록 전체 조회를 서버 캐시한다. 게시글이 바뀌어도 최대 5분 뒤
  검색에 반영된다.
- 정적 페이지(회사소개·고객지원 등)와 실시간 자동완성·인기검색어는 범위에서 제외했다.
